# 2026-11-11 演示前加固

投递前一轮代码硬化，目标是「演示视频里跑到的链路不能有说不清的报错」。改了六处，全量单测 **585 passed**（原 584 + 新增 1 项），演示冒烟 8/8 PASS。

## 1. 在线检索策略改为配置驱动，默认 hybrid_rerank

`RAG_STRATEGY`（`app/config.py`）成为唯一开关，`retrieve()` 留空即读配置。改动前 `DEFAULT_STRATEGY = "dense"` 写死在代码里，而：

- 置信度闸阈值 0.45 是 `scripts/calibrate_gate.py --strategy hybrid_rerank` 扫出来的（见 `reports/ch09_gate_calibration.md`），线上却拿 dense 的相似度去比这个阈值——**闸的量纲和标定量纲不是一套**；
- 定时评估也默认 hybrid_rerank，趋势图量的不是用户实际拿到的检索。

所以不是「换个默认值」，是把三条链路的策略口径统一到一处配置。

**代价要说清楚**：CPU 上跑 bge-reranker-v2-m3 很贵。同一条冒烟里，退款子流程一轮从 4.8s 涨到 37s，写操作确认流从 12s 涨到 48s（多路检索每路各精排一次）。内存紧或要现场流畅，`RAG_STRATEGY=dense` 一行切回，其余逻辑不动。

顺带修了预热：只有精排档才加载重排模型，切 dense 不再白占 2.2G。

## 2. 写操作确认闸默认值反过来（fail-closed）

`ToolExecutor.execute(confirmed: bool = True)` 改成 `False`。原来「不传即视为已确认」，权限闸的设计意图被默认值反掉了——两个 HTTP action 接口（`/chat/actions/create-ticket`、`/refund/apply`）和 CH02 遗留链路都没传。

改默认值后必须同步处理调用点：

- `routes.py` 两个 action 显式传 `confirmed=True`——业务语义上这两个接口是「用户点了表单按钮」才发的请求，确认发生在前端；
- `react.py` 本来就显式传，不动；
- `naive_loop` / `tool_chat` 是 CH02 遗留链路，不给确认态，写操作会被拒——这正是想要的。

## 3. 一轮对话落库收成一个事务

`message_repo.add_message` 加 `commit=False`（只 flush），`_persist_turn` 把 user + N 条工具轨迹 + assistant 收成一次提交，失败整体 rollback。摘要那边同样：`add_summary` 与 `advance_anchors` 原来各 commit 一次，后者失败会留下「梗概已落、锚点没动」，下一轮把同一段再压一遍。

逐条 commit 的写法留下的半截历史不会自愈——下一轮回灌 LLM 就按错历史推上下文。

入池（`flywheel.enqueue`）从事务里挪到事务之后：它是旁路，失败不该把已经答完的一轮回滚掉。

## 4. 图跑挂时这一轮也要留痕

原来 `astream` 抛异常只 yield 一个 error 帧就 return——token 早推给前端了，用户看到半截回答，库里却什么都没有，下一轮读历史缺这一轮，用户说「刚才那个」系统接不上。

现在异常分支落一条 user + 一条明确的「本轮中断」占位。回灌时模型知道这轮没答成，不会当成正常上下文。

## 5. 后台主题页去 XSS

`topics.js` 把用户原话拼进 `innerHTML`，而同目录的审核页早就用 `textContent`——两个后台页安全实践不一致。改成 `createElement` / `textContent`，`data-label` 用 `dataset` 赋值，不再过字符串。

## 6. 文档与依赖

- 补 `onnxruntime`（ONNX 推理与 `scripts/topic_demo.py` 必需，原来 requirements 里没有）；
- README 去掉重复的 torch 安装命令（会和 requirements 里的锁版本打架），补「模型权重」下载命令与「零依赖演示」启动方式；
- `httpx2` / `httpcore2` 不是可疑包：实测是 langsmith 的依赖（pydantic 组织维护），审计报告那条判定可以撤回。

## 没动的

- 检索故障仍伪装成「零命中」拒答（`query_faq` 降级 LIKE 后无引用编号）。演示库是本地文件，故障概率低，改动要碰闸的语义，留到演示后。
- eval 主脚本仍恒定返回 0、裁判失败按「忠实」计。要动得同时定阈值，否则 CI 一接就红，风险大于收益。
- 后台与写接口无鉴权：README「边界」已明示本地/内网演示定位，不改。
