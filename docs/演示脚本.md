# 演示脚本（录制版）

一镜到底的逐条清单：每一幕都是「输入什么 → 屏幕上会看到什么 → 这一下要讲什么」。
耗时来自 `reports/demo_rehearsal.md`（`scripts/demo_rehearsal.py` 在真服务上逐幕实测），
不是估的。换环境换模型后先重跑一遍彩排再录。

## 0. 录制前五分钟

```bash
cd /d/客服agent

# 演示库：986 块知识库 + 演示用池子数据
# 注意 DATABASE_URL 要显式给：.env 里写的是 MySQL 3307，本机 Docker 没起
DATABASE_URL="sqlite+aiosqlite:///./data/ch07.db" \
VECTOR_STORE_URI=./data/ch07_milvus.db \
LANGFUSE_ENABLED=false \
python -m uvicorn app.main:app --port 8000
```

三个页面按顺序开着（浏览器标签从左到右）：

| 标签 | 地址 | 录哪一幕 |
|---|---|---|
| 1 | `http://127.0.0.1:8000/?xray=1` | 全部聊天幕（xray=1 打开演示视图，内部状态才看得见） |
| 2 | `http://127.0.0.1:8000/admin/review/` | 飞轮审核 |
| 3 | `http://127.0.0.1:8000/admin/topics/` | 主题分布 |

录制参数：浏览器缩放 110%~125%（投影和录屏都够大）、关掉其他标签与通知、
终端字号调到 16 以上（飞轮那幕要露一眼命令行）。

开录前先随便问一句把模型热起来——首请求要加载嵌入 + 重排模型，冷启动那 1~2 分钟
不要留在录像里。

## 1. 幕单

时长是单轮真模型往返（含检索/重排/生成），取自 `reports/demo_rehearsal.md` 的那一轮：
彩排里十三条打点串起来 3.9 分钟，加上口播和操作大约 6~8 分钟一条片子。同一轮里
第一幕花了 40 秒、第三幕只花 5 秒——差在要不要生成长答案，别按平均算。

### 第一幕：一次问两件事（约 40 秒）

> 输入：`LP500 和 LP300 差在哪？我一天出三十杯左右该选哪个`

看：底下的流程芯片一路点亮（指代消解 → 意图 → 置信度闸 → 检索 → Agent），
答案里带 `[1] [2]` 角标，点角标右侧抽屉弹出「来源原文」章节路径。
演示视图面板里能看到闸的 top1 分数和每条证据的得分。

讲什么：一句问句里拆出两个诉求（差异对比 + 选型建议），检索按重写后的问法走
混合召回，答案的每个数字都能点到出处——「不服气可以点开看原文」。

### 第二幕：同话题深挖（约 30 秒）

> 输入：`咖啡机多久除一次垢`

看：答案给出周期（30 天）和判断依据（TDS 区间 → 软化滤芯 → 90 天），
引用指向「咖啡机清洁除垢与耗材管理 > 除垢周期」。

讲什么：这类细节问题最能看出检索是不是真命中——答案是从「水质判断」和「除垢周期」
两小节里各取一条拼出来的，不是把整段话糊上来。

### 第三幕：查物流（约 5 秒）

> 输入：`订单1003的物流到哪了`

看：答案上方两个工具徽章依次从「调用中…」变绿成「完成」，答出来的是带时间地点的轨迹。

讲什么：这不是检索能答的，是 Agent 自己决定调 `query_order` + `query_logistics` 两把工具，
多步 ReAct；工具超时、参数不对、系统内部错误各有分流，不会把异常当答案说给用户。

### 第四幕：指代 + 政策（约 27 秒）

> 输入：`那能改地址吗`

看：上方出现系统气泡「已补全为:订单1003……」，然后走知识库答改址规则。

讲什么：用户没说哪个订单，系统从上一轮拿 1003 补全，补全结果明明白白显示出来，
不是偷偷猜。改址能不能成取决于发货状态，这单运输中，答案是「拦截」而不是「改」——
政策条款和订单事实要对上。

### 第五幕：退款判断（两轮，各约 20 秒）

> 输入①：`订单1003能退吗`
> 输入②：`那订单1007呢`

看：两轮都走「退款子流程」（流程芯片里多一个 `refund_subflow` 节点），
结论不一样：1003 还在运输中 → 「现在不能退，得等签收后再发起」；
1007 已签收 → 直接给出 15 天无理由的条款和需要保持完好的条件。

讲什么：这一步的顺序是写死在图里的——先 `query_order` 拿这一单的事实，
再扩写多路检索政策，两道都过了才让模型做判断。模型只负责最后那句需要理解力的话，
「查什么」不让它决定，因为判错一次就是赔钱。

### 第六幕：缺订单号（约 2 秒）

> 输入（新会话）：`我要退货`

看：回三张订单卡片（商品、金额、状态），点一张直接把订单号填进去。

讲什么：模型不许猜订单号，猜错等于把别人的单子退了。宁可多问一句。

### 第七幕：投诉升级（约 2 秒）

> 输入（新会话）：`我要投诉，订单1001的耳机拆开就是坏的`

看：不调任何工具，走固定安抚话术，底部两个按钮「转人工」「建工单」。

讲什么：情绪类请求不走 Agent，固定话术保证不失言；升级动作交给人点，
系统不自作主张。

### 第八幕：写操作确认（两轮，约 9 秒）

> 输入：`订单1001的包裹好像被放错地方了,帮我建个工单让专员查`
> 动作：点卡片上的「确认提交」

看：先弹一张确认卡片（工单类型 + 描述），点确认之后才出现「已建单 + 工单号」。

讲什么：所有写操作都在图里拦一道 `interrupt`，引擎只认「用户点过确认」这个布尔值；
恢复执行会把节点重跑一遍，所以落库的参数以用户看到的那张卡片为准。

这句问法得落在 business 路才走 Agent 建单，两个坑：带「投诉」二字会被判成投诉路
（回一段安抚话术）；带「没收到货/已签收」会被判成退款路（去查订单和政策）。
问「包裹放错地方」正好落在物流路，Agent 才会调 `create_ticket`。
真要演示投诉的升级按钮就用第七幕那两个——按钮本身就是确认动作，点下去直接建单、不弹卡片。

### 第九幕：拒答（约 26 秒）

> 输入（新会话）：`你们卖儿童安全座椅吗`

看：答案明确说「这个我不知道」，语气不敷衍，下面同样给「转人工」按钮；
演示视图面板里闸显示拦下（top1 只有 0.01）。

讲什么：闸卡在生成之前，一旦说过头了收不回来。库里没有的知识点，宁可说不知道——
这一条比答对十道题更能说明系统可信。

问法要挑成「商品咨询 / 产品咨询」类（卖不卖、能不能定制），别问成「能不能带上飞机」
那种：后者会被判成「其他」直接交给 Agent 自由作答，压根不检索、也不进闸——现象一样是
「答不上来」，但展示不出闸和入池。

### 第十幕：飞轮闭环（这一段是重点，约 1 分钟）

四步连着做：

1. 刚被拒答的那句话已经在池子里了（`low_confidence_questions`）。
2. 切终端跑一句：`python scripts/run_flywheel.py --batch 20`
   → 打印「处理 N 条 / 新建缺口 M / 累加 K」，这些原话被标准化 + 查重后进了待审队列。
3. 切标签 2（`/admin/review/`）→ 待审队列最上面就是这条 → 点开能看到当时的召回快照
   （「知识库真缺」还是「有但没检到」，审核人靠这个判）→ 填答案 → 点「通过并写入知识库」
   → 提示「已通过，知识库已更新」。
4. 切回聊天，换个问法再问：`你们有卖儿童安全座椅吗`
   → 这次答得出来，引用里出现刚刚补进去的那条。

讲什么：这不是「重新训练模型」，是把人的答案变成知识库里的一条块，
下一轮检索就能拿到。系统的能力随使用增长，而且每一次增长都有审核留痕。

### 收尾：两个后台页（30 秒）

标签 3（`/admin/topics/`）：17 类主题分布条形图——「用户都在问什么」是运营视角。

回标签 1 点右上「演示视图」，把某一轮的内部状态面板展开定格一拍：
意图置信度、闸分数、证据、工具轨迹、trace 名。这一屏是给技术面试官看的。

## 2. 每幕的备用问法

模型是非确定性的，同一句问法偶尔会换个说法或先追问一句。下面这些是等价问法，
录的时候哪句不顺就换哪句，别现场调试提示词。

| 幕 | 主问法 | 备用 |
|---|---|---|
| 一 | LP500 和 LP300 差在哪？我一天出三十杯左右该选哪个 | LP500 适合开店用吗 / 家用和商用咖啡机怎么分 |
| 二 | 那连续做三杯要等多久 | 连续出杯需要间隔吗 |
| 三 | 订单1003的物流到哪了 | 帮我查下 1003 走到哪了 |
| 四 | 那能改地址吗 | 地址填错了能改吗 |
| 五 | 订单1003能退吗 / 那订单1007呢 | 这单能退吗（先说清订单号） |
| 六 | 我要退货 | 我想退款（新会话，不带单号） |
| 七 | 我要投诉，订单1001的耳机拆开就是坏的 | 收到的耳机是坏的，我要投诉 |
| 八 | 订单1001的包裹好像被放错地方了,帮我建个工单让专员查 | 帮我建个工单,让专员查一下订单1001的派送记录 |
| 九 | 你们卖儿童安全座椅吗 | 你们的睡袋能定制颜色吗 / 你们的帐篷能印 logo 吗 |

第九幕的题是耗材：补进知识库之后就不能再用它演「拒答」了。两条路——换
`scripts/demo_rehearsal.py` 里 `FLYWHEEL_CANDIDATES` 的下一条，或者把这条回滚掉再来：

```bash
python scripts/flywheel_reset.py --keyword 安全座椅 --dry-run   # 先看会删什么
python scripts/flywheel_reset.py --keyword 安全座椅             # 删块 + 删向量 + 审核行置回待审
```

彩排脚本跑完会自动回滚（不想回滚加 `--keep-flywheel`），所以同一套词可以反复走。

## 3. 不要做的事

- 不要现场让面试官即兴出题。库里没有的领域会被拒答，那是设计，但在没铺垫的情况下
  看起来像不会。要展示拒答就按第九幕的节奏来。
- 不要连着问超过五轮。上下文预算在，但每轮 15~25 秒的等待连续堆起来会让节奏塌。
- 不要在录像里展示 `.env`。里面是 key。
- 不要用 `.env` 默认的 MySQL 起服务。本机 Docker 没起，起不来就是零分。
