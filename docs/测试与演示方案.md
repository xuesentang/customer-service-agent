# 测试与演示方案

面向两个目标：① 实习投递 + 线下演示不能出错；② 让"看不见的亮点"可验证、可展示。
2026-10-25 状态:第 1 节的测试失败已修(全量 584 绿),冒烟脚本与演示库重建已落地(`scripts/demo_smoke.py`),证据一页纸在 `reports/demo_evidence.md`,X 光演示面板已做(默认关)。

## 0. 结论

1. **机器能测的已经覆盖约八成**：584 项单测 + 每章 eval + README 各章验收命令。真正缺的只有一块——**演示冒烟**（一条命令验证"服务起得来、八条主路径全通"）。演示日最大的事故不是模型答错，是环境起不来。
2. **手动只留四类**：LLM 回复的人话质量、多轮指代自然度、前端交互细节、现场环境（网络/投影/密钥）。机器判"对不对"已由 eval 覆盖；"好不好、像不像人"只能人读，合计半小时过完。
3. **"亮点看不见"是证据出口问题，不是设计问题**。数字已全部存在（分类 F1 0.9687、混合检索 R@5 0.84、意图 38/38……），缺三样：一页证据表、一个默认关闭的「演示模式」把 SSE 里已经在飞的数据显示出来、一条固化的演示脚本。前端主界面不用动。
4. **演示日最大风险已发现一个实证并已修复**：`.env` 的 Langfuse 开关导致全量 pytest 挂 1 项（测试间 client 泄漏）。2026-10-25 已修（conftest 隔离，584 全绿），根因记录留在第 1 节——这个坑值得在面试里讲。

## 1. P0（已修）：全量测试曾因 Langfuse 开关挂 1 项

**现象**（2026-10-25 实测）：`python -m pytest` → 583 passed / 1 failed，败项 `tests/test_langfuse_tracing.py::test_traced_wraps_retrieve_and_emits_span`，断言 `rag.retrieve` span 数量 0 == 1。单独跑该文件 16/16 全绿。

**根因链**：

1. `.env` 第 46 行 `LANGFUSE_ENABLED=true`，且填了真实 Cloud key（云端验证后留下的状态）。
2. 全量跑时，先执行的 `test_agent_chat_service.py` / `test_context_wiring.py` 等走真实 `chat_with_agent` 链路 → `open_chat_trace` → 工厂按 .env 配置 `_build_client` 建了一个**真实 Langfuse client**（host 可达）注册进 SDK 全局表 `LangfuseResourceManager._instances`。这些测试不知道要清理它。
3. 轮到 langfuse 文件时进程内已有 2 个 client 实例；`@observe` 装饰的检索函数用 keyless `get_client()`，SDK 的多实例保护（防跨项目串数据）直接拒绝 tracing → span 不落内存 exporter → 断言失败。
4. 单独跑该文件时前面没有真实 client，只有用例自己的 1 个实例，所以绿。

**修法与结果**（`tests/conftest.py` 两个 autouse fixture，不动 `.env`）：默认把 `LANGFUSE_ENABLED` 压成 `false`（要开着测的用例自己显式 setenv——langfuse 文件的 fixture 本来就是）；每个用例结束后摘掉 `LangfuseResourceManager._instances` 里新增的实例 + 清 `tracing._callbacks_for` 的 lru_cache。修完全量 **584 passed**（且从 137s 降到 107s——不再往真实 Cloud 发测试 trace）。附带伤害也一并消除：单测不再把测试数据写进 Langfuse Cloud。

### 2.2 缺口（已补）：演示冒烟脚本 `scripts/demo_smoke.py`

**为什么单测不够**：单测跑内存库和假模型，证不了"服务真的起得来、SSE 真的出事件"。演示日第一句话之前，需要一条命令回答"现在能不能演"。

**规格**（准备 → 执行 → 断言，退出码非零即红）：

- 准备：服务由脚本进程内起（uvicorn 线程，devstack 参数：SQLite + Milvus Lite；Langfuse / MCP 强制关——冒烟只验聊天主链路）。**不要用 `.env` 默认的 MySQL 3307**，本机 Docker 不可用，用错命令直接起不来。
- 执行：8 条探针顺序打 `/api/v1/chat/stream`（真模型、真库、真 SSE），覆盖全部出口。
- 断言（SSE 事件序列）：

| # | 输入 | 必须出现 |
|---|---|---|
| 1 | W20 有宽楦版本吗 | `intent(route=knowledge)` → `node(retrieve_knowledge)` → `gate(passed=true)` → `citations` → 答复非空 |
| 2 | 订单 1001 的物流到哪了 | `route=business` + `query_logistics` 被调用且 `tool_end` 全 ok |

| 4 | 我要投诉你们，订单 1001 的耳机收到就是坏的 | `route=complaint` + `done.actions` 含 `transfer_human` + `create_ticket` |
| 5 | 你好呀 | `route=chitchat`，无 `tool_start`，`finish_reason=chitchat` |
| 6 | W60 用的碳板是第几代 | `gate(passed=false)` + `finish_reason=abstain` |
| 7 | 我要退货（新会话） | `order_options`(3 笔) + `finish_reason=need_order` |
| 8 | 建工单（真模型两轮内要卡）→ resume approve | `interrupt` 卡片 → `done` → tickets 表恰好 1 行 |

## 5. 亮点可见性方案（核心）

问题：混合检索、分类微调、飞轮都在后端，聊天框里只看到答案。**但数据其实已经在往前端飞**——SSE 事件里 `intent` 带 confidence、`gate` 带 top_score/reason、`tool_start/tool_end`、`citations`（含 score）全有，前端只把节点名渲染成一行小芯片（`chat.js` 的 flow-line），数字没显示。

### 5.1 零成本层（现在就能演）

| 亮点 | 观众看哪 | 你说什么 |
|---|---|---|
| LangGraph 编排 | 每轮回答上的流程芯片：指代消解→意图识别→置信度闸→Agent | "能确定的写在图里，不确定的才给模型" |
| 混合检索 + 引用 | 答案里 [n] 角标，点开右侧抽屉看来源章节与原文 | "两路召回 RRF 融合 + 重排，答案必须带证据" |
| 拒答闸 | 问库外问题，答复明确说不知道 + 转人工/建工单按钮 | "闸在生成前，说错了收不回来" |
| 主题分类 | `/admin/topics` 17 类条形图 | "微调模型旁路归类，看问题分布" |
| 数据飞轮 | `/admin/review` 待审队列 + 召回快照 + 评估趋势 | "拒答和 👎 自动进池，人审后回写知识库，下一轮就能答" |
| 可观测 | Langfuse 云端 trace 树（根 span→节点→generation→retriever） | "一轮对话一棵树，prompt/usage/耗时全记录" |

### 5.2 演示模式（已做，主 UI 零改动）

顶栏「演示视图」按钮或 `?xray=1` 打开（状态记 sessionStorage，刷新不丢），每轮回答的决策流下方多一个可折叠面板：

- 意图 + 置信度（`intent` 事件）
- 闸：top_score / confidence / reason（`gate` 事件）
- 证据列表：每条 section + 分数（`citations`）
- 工具轨迹：调用名 + 成败 + 摘要（`tool_start/tool_end`）
- 补全后的原话（`resolved`，指代消解的证据）
- 终态 finish_reason + trace 名 `chat:{conversation_id}`（在 Langfuse 里搜这个名字）

全部数据来自既有 SSE 事件，零额外请求；普通用户看不到这个面板——调试视图与用户界面分离，ChatGPT / Langfuse playground 都是这个模式。"前端简洁"和"亮点可见"不冲突。

### 5.3 终端管线演示（不想动前端的备选）

`scripts/tool_demo.py` 有先例。笔记本接投影，左边聊天框右边终端，`agent.trace` 一行一轮（intent/route/gate_passed/top_score）。
